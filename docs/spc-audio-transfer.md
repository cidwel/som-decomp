# Native SPC transfer receiver and sample-cache movement

`tools/spc_audio_transfer.py` reconstructs the complete receiver chain **SPC 11EA..12AB, 194 instruction bytes**, physically **ROM C31734..C317F5**. It includes dispatcher 11EA (42), triple-packet receiver 1214 (35), pair receiver 1237 (26), byte receiver 1251 (18), idle acknowledgements 1263 (13), and cache movement 1270 (60). `tools/spc_audio_transfer_source.py` supplies independent fixed mnemonic source and regenerates the **16 numeric target bytes at SPC1418/ROMC31962**. All 194 code bytes and sixteen table bytes match the ROM independently. The shared manifest and joint source proof include these bytes with separate SPC/65816 counters; helper bodies are proved through the11EA trampoline rather than standalone helper contracts.

The dispatcher retains all original packet flag bits at direct-page 04, selects the low three command bits, publishes the masked command through output port F5 and loads the input destination word. Its **real return trampoline** pushes the selected handler's address onto the native stack; RET enters that handler while retaining the original caller return. The proof begins at original 11EA and executes those actual pushes/returns, rather than replacing them with generic function calls or hooks. A zero low command returns immediately. Types one, two and three upload one, two and three bytes per packet; four, five and six share the idle handler; seven moves cache blocks.

The readable receiver preserves each packet's original acknowledgement position, Y changes, word-pointer increments and arithmetic flags. Triple packets update the destination using two byte ADCs with carry, while pairs and bytes use the original word increment behavior. The idle handler acknowledges until the input token becomes zero. All handlers return to the dispatcher by their original branch/jump; the final zero-command header supplies retained final flag bits.

Cache movement receives destination and length packets, copies bytes **forward** with literal overlap behavior, increments source/destination high bytes on Y wrap and decrements the complete word count. It can accept further source/move packets before the terminating zero token returns to the dispatcher. The model preserves native pointer-high effects and residual Y, including word-length boundaries. Zero length would copy 65,536 bytes and can destroy executing code; it is explicitly outside this proof domain rather than silently interpreted as empty.

`PacketApu` is an explicit external sender boundary: an acknowledgement schedules the next packet, but payload ports remain stable until the receiver's first subsequent token read. This is necessary because several native handlers acknowledge before reading the last payload bytes. The producer then changes the token and payload together. No instruction is skipped or replaced. This establishes functional protocol behavior for that valid handoff, not physical bus timing or concurrency behavior of every possible sender schedule.

The final proof terminated with exit 0: **1,024 complete original dispatcher chains**, **100 PC/P states**, **8 fresh hashes**, **7,165 ordered I/O writes**, **194 matching instruction bytes** and **16 matching numeric bytes**. It covers all eight types, packet flags, nonzero token wrap, one through eight upload packets, one through three cache moves, move lengths 1/2/255/256/257/512, byte carry and forward/backward/equal overlap cases. DMA destinations are restricted to safe RAM regions around 2800, 5000 and 6000; arbitrary program/stack corruption is not included. It compares random 64 KiB RAM with all native upload blocks restored except four caller/trampoline stack bytes 01EC..01EF, all processor/SP/PC, DSP/ports/control/targets, ordered I/O writes and external producer state. All captured comparisons pass. The six literal SPC sources and the typed numeric `.word` source are described in the separate manifest proposal.

```sh
python3 tools/spc_audio_transfer.py 'baserom.sfc' \
  --json data/spc_audio_transfer.json
```

The command receiver 0CAF, complete music setup 0CF1 and sequencer/voice execution remain open. This closes their transfer dependency without claiming the full driver or synthesizer is decompiled.
