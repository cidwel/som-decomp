# Map-character initializer controls and native zero-count continuation

`tools/map_character_initializer_control_contract.py` models the complete original C1B17E setup and the C1B1C3 return-control suffix. `tools/map_character_zero_count_record_contract.py` adds the record behavior needed when an enabled zero-count list passes16 records. These add no new recovered bytes and leave existing PASS reports unchanged.

`data/map_character_initializer_control_proof_20261013.json` is PASS with570,938 original opcodes:67 setup cases,12 return-control cases and one authentic header43 zero-count composition through32 complete original record bodies. Every comparison covers all CPU17 and all CPU/bus fields except the instrumentation step counter, including all private stack writes, WRAM/SRAM, VRAM/CGRAM and ports/latches, DMA and base hardware. No hooks, callee skips, stack exclusions, patched ROM or synthetic graphics/descriptors are used. Original ROM and volatile random VRAM provide the data. The PPU/DMA accuracy remains that of the existing loader_ppu/wram_dma forced-blank bus model.

The setup cases cover all64 selectors, two disabled contexts and a bit7-set zero-count context. Disabled headers return normally. Every enabled header enters B1BF even when the capped count is zero. The original code has no empty-list branch. The suffix restores descriptor X with16-bit PLX, increments it twice, decrements DP10 with16-bit DEC, branches back whenever the result is nonzero, and otherwise restores saved DB and returns with RTL. Separate count0/1/2/16/8000/FFFF cases verify both branch paths and exact stack/CPU/bus effects.

If every body returns and nothing aliases DP10, a zero count requires65,536 decrements to reach zero again: the first decrement is0→FFFF. This is a conditional property of the caller control, **not a claim that the initializer actually completes65,536 records**. Transform termination, index truncation and workspace aliasing are additional conditions.

The actual header43 means selector3, whose original start/end pointers are both0694. This composition executes32 genuine records from C80694 through C806D2. It reaches the next original B1BF head with X06D4, DP10FFE0 and DP06F200. Every original DMA/dispatch/frame callee is executed. The proof compares the independent record/frame model and exact net stack effects at each real B1C3 callee return, then compares the independent caller suffix at the next loop head.

The new semantic finding is that record writes use the full16-bit DP14 index, but SEP30 truncates X before the final `LDA $8201,X` dispatch. After16 records, the dispatcher reads an older record from the first256 bytes while the new record is stored farther into the table. At body19 the original word has type7, but the actual dispatcher reads old type12; bodies20/21/22/23 dispatch4/12/12/4 while their newly stored types are7/9/4/9. Bodies24..32 store type15 and dispatch type4. The previous record model's positive-list domain did not encounter this distinction because native positive lists are capped at16.

The adapter retains existing frame algorithms and adds the two index domains. In this bounded original prefix every dispatched type is4 or12. Its complete-body contract also derives the persistent final stack pushes from the original wave and mirror call sites, including final wave indices15 and7. This closes private-stack effects for those actual bodies without masking or copying reference stack bytes. Other dispatched types and arbitrary alias/wrap domains are outside this new complete-body adapter.

The existing `data/map_character_animation.json` remains the evidence for730 complete positive/disabled original initializations and the count-cap guard; it is hash-pinned and reused rather than rerun. Its original stack-exclusion scope is unchanged. The earlier type11 API composition remains independent and is not repeated here. No native type11 appearance is claimed by this zero-count prefix. Complete zero-count termination, later record/graphics aliasing, the full type11-enabled initializer entry, interrupts and rendering/timing remain open.

The new report pins eleven tool dependencies, thirteen recovered source files, the prior positive initializer proof and the ROM by SHA256. Source credit is zero.
