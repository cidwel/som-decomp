# Native SPC high macro commands, fade setup and voice control

`tools/spc_audio_macro_commands.py` reconstructs the complete **SPC0FF9..11E9 interval, 497 instruction bytes**, physically **ROMC31543..C31733**. The independent fixed mnemonic bodies in `tools/spc_audio_macro_commands_source.py` already regenerate those 497 bytes exactly against the ROM. The **64 numeric target bytes at SPC14B2/ROMC319FC** are generated from the native 32-target list. Existing control helpers at 12AC/12C6/12DD receive no duplicate candidate credit.

The dispatcher preserves native return trampolines: commands below 90 or at/above F0 select a target by the low five bits, push its address and RET into the handler; commands 90..EF return after the native comparisons. The proof will enter original 0FF9 and execute that actual stack protocol. The main receive function 0CAF separately intercepts command FE for data transfer, so a direct FE macro-dispatch call does not establish its gameplay route. Zero-op target aliases remain literal one-byte returns.

Three parameter handlers configure the accumulators advanced by the separately reconstructed 13E5 fade routine. They retain the high nibble as duration, decode the original target scaling/sign transform and store the target byte. Zero duration or zero difference takes the original immediate path, clearing phase fraction/velocity and setting the appropriate dirty voice mask. Otherwise they compute the complete fractional velocity from the magnitude and duration through two original divisions, restore the saved subtraction PSW, apply the original signed complement/increment and write the word step. The readable model uses the equivalent complete fraction `floor(absolute_difference*256/duration)` with the native minimum-one fallback. Native nonzero durations are 16..240, avoiding undefined division; the sign, low byte, high byte, scratch word, indices and final PSW are all preserved. Source includes all native division instructions, even though their transient status is discarded by POP PSW.

The remaining handlers set mix bits, preserve the native complementary voice-group masks, clear only the specified pending bytes, mark upper flags, set/snapshot control bytes and toggle the parameter-derived bit. The pause/resume body writes every voice's ADSR control and clears left/right volumes on pause, saves/restores the complete voice mask and clears the exact scale bytes. Its use of the word at direct page zero as a zero anchor is **literal**: the model reads that word rather than substituting a fabricated constant. Driver initialization normally clears it, while the proof can expose arbitrary contents mechanically. Native byte masks, flags and ordered DSP/port writes are preserved throughout.

The captured extensive proof passed **5,120 complete original entries**, with 264 PC/P states, 9 dependency hashes and 17196 ordered I/O writes. These comprise 512 for the dispatcher and each of its nine contiguous handler bodies. It covers high commands 80..FF, all operand bytes in direct handlers, native P0 flags, fraction/sign/byte boundaries, random RAM/DSP/ports and pause masks. It compares all RAM except five native caller/trampoline/saved-PSW stack bytes 01EB..01EF, CPU/SP/PC, DSP/address, ports, control/targets and ordered I/O. Whole uploaded code is restored without request stubs and executes without hooks. Timer inputs/progression use the explicit existing peripheral boundary, with no hardware timing/waveform claim. The process completed terminal exit zero; its full functional report is saved in `data/spc_audio_macro_commands.json`.

```sh
python3 tools/spc_audio_macro_commands.py 'baserom.sfc' \
  --json data/spc_audio_macro_commands.json
```

The complete receive entry 0CAF, music initialization 0CF1, sound-effect handler 0E10 and voice sequencer remain open. Closing these high-command dependencies does not claim the whole SPC driver is decompiled.
