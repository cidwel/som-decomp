# Controller movement and active contact/motion composition

C0B710–B798 is a complete 137-byte movement producer with 67 own instruction starts. Every start and immediate M/X width is observed in passing original entry calls; its readable source independently assembles exactly to the ROM. `data/hero_controller_motion_source_audit.json` records the proof, capture and assembled-source hashes.

The producer reads controller direction bits from DP10, decodes horizontal and vertical magnitude-two signed velocities and packs them through the original XBA/TAY operations. It clears action bits30 when the controller's high direction byte does not request the corresponding mode. Shifting the one-hot controller/hero selection in DP11 selects hero offsets0000/0200/0400. The selected hero's E067 byte is cleared before the inhibition, activity/status and special-action guards.

Action bit80 first publishes E01D; pose2 returns without replacing the live velocity. Other action states consume bit80 and test E063's low bit. A previous negative E01D state also requests the E1ED update: binary byte subtraction of E189 from100, shift-right and add50, preserving native carry/overflow. Accepted motion publishes the remaining action byte and the packed signed velocity word to E006/E007. The original return width and flags are retained; the entry ABI is M8/X8 and the velocity publication returns M16/X16.

The frozen proof passes 111 scenarios, 116 complete original routine calls and 10,513 instructions. Direct cases cover all sixteen direction combinations, all three selected heroes, action modes, energy/previous-pose branches and each early guard. Five further scenarios call the original producer and then the complete original C0D5C0 contacts/hero/NPC movement caller in order, using the new `HeroControllerMotion` model over corrected `SharedMotion`. Full original contacts, ground, actual terrain and camera callees execute. The caller's already adopted45 bytes and downstream helpers receive no additional source credit.

On ROM-produced map16, the composed horizontal/vertical cases move the hero from (296,376) to (298,376) or (296,378). A diagonal case reaches (298,378); negative cases reach (294,376) or (296,374). Three scenarios also move an active NPC from (408,344) to (409,344), with the actual actor pool enabled. Comparisons cover WRAM outside the measured native stack, SRAM, logical CPU/context, peripherals and ordered audio after each call. No hooks, ROM patches, shortened native calls or saved payloads are used. Frozen Hero641/NPC226/Shared1267 models and reports retain their hashes.

Controller/hero selection, action and actor state are explicit caller ABI inputs. This verifies the complete producer and its ordered movement continuation, not hardware polling or the whole C0B69C input caller. That caller invokes C0B799's attack/charge scheduling, including C0B330, C0B851 and existing attack services; those dependencies must be completed before a full input/frame claim. Continuous frames and cycle timing remain open.
