# Event flag assignment and actor movement

The new readable model reconstructs three complete event command families:30 atC1EE8C assigns a script byte to a flag while OR-preserving the old upper nibble;31 atC1EEA9/EEAF selects an actor, performs the full original charge cancellation and cached/weapon palette cleanup, assigns motion and resumes event dispatch;32 atC1EEEA selects an actor, separates speed and direction, writes cardinal velocity and applies the original nonparty presentation gates. The300 instruction bytes across four complete intervals now independently assemble byte-exactly after8496 complete original calls.

Command30 deliberately returns directly after advancing D1 bythree. It does not resume the dispatcher inside this handler. Its payload is not masked to a low nibble: upper payload bits are ORed with the existing upper flag bits. The long script reader carries into the next bank when reading its argument; the stored script word advances modulo65536 while D3 remains unchanged.

Motion31 distinguishes the current actor (selector0), explicit heroes1..3, and the NPC alias when bit7 is set. It reuses the independently proven MotionCleanup.clear_motion without modifying that model. Velocity32 also admits positive selectors through the twelve declared aligned actor slots. A zero low-six-bit speed stores speed1 with an inactive movement mask; each high-two-bit direction writes its original signed/cardinal velocity bytes. Party actors exit after velocity/facing setup, while NPCs set publication field30 and consult bits20/40 offield71 for presentation. Later motion or gameplay frames remain outside this proof.

The verified checker covers all256 payloads at twelve sampled flag identities, all256 motion bytes for six actor aliases, all256 direction/speed bytes for twelve physical actors and current/NPC aliases, direct motion-helper stack entry and calls through the actual event dispatcher. Original cleanup dependencies retain their existing valid palette cursor domains; full random WRAM outside observed stack, CPU/context, static video/arithmetic state and audio acknowledgements are compared. Native command entry isM8/X8,D0,DB7E,binary. Flag/helper pointer-boundary cases do not invent a bank update. Unknown event commands still raise unresolved dependencies.
