# Readable SPC driver initialization and echo configuration

`tools/spc_audio_initialization.py` begins actual readable reconstruction of the **SPC700 program** uploaded by the 65816 boot routine. It models SPC 0200..0278 (121 bytes), the DSP write helper 061B..061F (5), echo configuration 12DE..132E (81), and echo-memory/filter publication 132F..138D (95): **302 recovered SPC instruction bytes**. The source manifest records their physical ROM addresses separately from their SPC execution addresses; joint source verification assembles the mnemonic files in `src/spc/` with the SPC assembler, independently of the 65816 assembler. `tools/spc_audio_initialization_source.py` provides independent fixed mnemonic bodies, named branch labels and an SPC assembler based on the public opcode metadata. Its regenerated 302 bytes already compare exactly with all four original ROM spans; The joint source report exposes both architecture totals; SPC coverage remains in its own report. The source is not generated by dumping ROM disassembly. The remaining driver and audio payload are not claimed recovered.

The first upload block begins at ROM C3074A and SPC 0200, so these entries map to ROM C3074A, C30B65, C31828 and C31879 respectively. The program itself remains unpatched: every fixture restores all six native upload blocks from the supplied ROM into randomized 64 KiB SPC RAM. No extraction request stub is installed and no original payload is written to the repository.

The readable initialization clears direct-page bytes 00..EF, initializes the stack, silences/configures the DSP, sets timer zero, chooses echo delay two and calls both complete echo helpers. It finally enables the native master volumes, initializes driver flags and clears eight bytes at FF80..FF87, stopping immediately before the main-loop call at 0279. The echo helper retains the previous delay, computes the unmasked echo start `FA - 8*max(1,delay)` modulo 256, initializes timer one and writes the native DSP registers. The second helper clears every byte of echo RAM up to FA00, waits for timer input, reenables echo, sets volumes and writes eight filter coefficients selected by the original low two filter bits, followed by feedback. Tables and program bytes are read only at runtime.

Timer-one reads are an **explicit peripheral input boundary**, with profiles one, alternating zero/one, three, and zero/zero/fifteen. The native SPC instructions execute normally through `spc700_cpu.Apu`; only timer input and approximate peripheral clock progression are isolated. The comparison establishes functional RAM, DSP, ports, control/target registers and CPU behavior under these supplied timer reads. It does not establish the interpreter's approximate timing, real timer phase, DSP audio synthesis or waveform equivalence. Both native read counts and ordered I/O writes are compared. Readable procedures are separate from opcode execution.

The final original-SPC proof terminated with exit 0: **1,024 complete entries**, **147 native PC/P states**, **6 fresh dependency hashes** and **302 independently regenerated matching instruction bytes**. It covers four complete bodies, all sixteen echo settings zero through fifteen, all sixteen prior DSP echo delays, filter bytes zero through 255, randomized DSP/ports/CPU and random RAM outside restored native blocks. P0 is the native driver context. It excludes exactly eight native caller/nested stack bytes at 01EC..01EF and 01FC..01FF. Final full RAM, A/X/Y/PSW/SP/PC, DSP/address, control/timer targets, input/output ports, timer-read count and ordered I/O writes all match. CPU cycles and timer phase are outside the explicit timer boundary. Coverage is recorded as native SPC PC/direct-page states in this model's own report, not mixed into the 65816 PC/M/X capture.

```sh
python3 tools/spc_audio_initialization.py 'baserom.sfc' \

```
