# Map scanline IRQ

The original C0BC85 vector installer copies the symbolic JML template C0BC93 into RAM0100/0104. The second vector reaches00C1CF, the ROM mirror of the complete24-byte map scanline IRQ. It narrows A, saves DB and the low A byte, selects DB0, acknowledges4211, writes BGMODE09 and main-screen mask14, restores A/DB, and executes RTI. The incoming high A byte remains intact through M8 operations. The native interrupt frame restores status and return PB/PC.

Eight original IRQ contexts and eight original vector installs passed on the first capture after a single smoke. All four incoming M/X combinations, D/DB contexts, pending0/1 and four low MDR values are covered. The comparison executes the real vector installer for each context, then injects a genuine native hardware frame and enters RAM0104. Memories/peripherals, ordered IRQ acknowledgement and all interrupted registers agree outside only the observed native stack. All own instruction starts execute through bank00, canonicalized to the same ROM offsets as C0C1CF. Audit/hashes are in `data/map_scanline_irq_audit.json`; model, checker, report and coverage are frozen.

The pending-bit read uses the existing scene interrupt CPU's literal4211 acknowledgement model. No instruction hooks, return substitution or temporary forced blank are used. Decimal mode and interrupt-disable status must be restored by RTI even though IRQ entry clears decimal and sets I. This establishes the callback and installed vector chain at a defined delivery boundary; asynchronous raster timing and a complete map frame remain separate. The installer/template are existing sources with zero new credit.
